- Trabajar y documentar en español. El estado del producto, sus contratos y sus decisiones viven en `docs/`; comenzar por `README.md`, `docs/DECISIONS.md` y `docs/ROADMAP.md`.

En CachyOS usar `experiments/phase1/.lab/` para cachés y perfiles. No instalar globalmente, modificar el host, usar cuentas reales, lanzar el stack de referencia, publicar releases ni implementar producción. No confundir Windows Server con Windows 11.
- La auditoría de Linux se limita a los ocho archivos enumerados en `docs/CURRENT_STACK.md`. Leerlos como texto; no seguir rutas a las que aluden, ejecutar scripts, consultar servicios, procesos, logs reales, credenciales, bases privadas o valores de claves. No alterar el host ni la infraestructura de referencia.
- No se encontró un flujo SDD en el repositorio inicial. Seguir especificación → decisión con alternativas y evidencia → criterios de prueba → revisión → cambio acotado. Conservar hechos, supuestos, propuestas e incógnitas separados. Citar etiqueta/archivo al introducir un contrato; verificar el artefacto publicado antes de prometer soporte.
- Preferir interfaces oficiales y composición; justificar cualquier fork con un fallo reproducible y plan de salida. Los permisos del agente, los límites del proveedor y el contexto de modelo son requisitos funcionales.
- Engram es secundario. Solo memoria de decisiones del proyecto; ningún dato de usuario, secretos ni consultas a bases compartidas en esta fase. Si se importa el resumen de `.engram/`, hacerlo en un almacén de proyecto autorizado. Ante divergencias prevalece `docs/DECISIONS.md`.
- Este repositorio es **público** (`UserTxmi/ai-stack-desktop`). Para el ciclo de trabajo autorizado: cambio acotado → validaciones locales → revisar status, diff, historial, archivos incluidos, autoría y secretos → commit descriptivo → verificar propietario y origin → push normal → consultar el workflow con `gh` → leer resultados filtrados → corregir la causa y documentar el resultado. No subir `.engram`, `.lab`, sesiones, perfiles ni diagnósticos crudos. Usar identidad pública/noreply para commits; no modificar auth ni configuración personal de Git.
- No duplicar con dispatch una ejecución por push. Un reintento solo con nueva evidencia o reparación concreta; si se repite la misma causa, detener y diagnosticar localmente. Documentación sola no requiere minutos Windows. Sin runners grandes ni cambios de facturación. Evaluar éxito por pruebas y artefactos reales, no por compilación o por pasos omitidos. Véase `docs/CI.md`.
