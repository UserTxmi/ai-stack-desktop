**26-11-2026 · Revisión del responsable del producto:** aceptados los doce entregables de fase 0 y las siguientes condiciones. Se autoriza la **preparación experimental 1A** en este repositorio. La aceptación de la arquitectura no certifica ninguna combinación Windows ni autoriza producción. La fuente de verdad es `docs/`, incluso si un resumen de Engram anterior aún dice «pendiente».

**Infraestructura aprobada; medidas experimentales para los bloqueos (no aprobación de fase 2):**

- D2/W1: la espera en cola debe ser terminal para esa petición, tanto para el limitador como para el cliente. Conservar la clasificación upstream basada en identidad del error en el camino no incremental. Autorizar en el laboratorio el backport versionado [omni_queue_fix.py](../experiments/phase1/omni_queue_fix.py) únicamente sobre cinco chunks de hashes conocidos. El tarball, Bottleneck y los relojes no se modifican. Retirar el backport al probar un artefacto upstream que supere la barrera sin él. Un run verde con el backport no certifica el tarball intacto.
- D3/W1: utilizar `reasoning_options` oficial y el bloque de proveedor producido por el plugin publicado; no copiar una lista visual ni implementar un descubridor paralelo. El perfil de laboratorio valida selecciones explícitas contra los tiers descubiertos antes de que OpenCode acepte el turno. Mantener hasta que el shim publicado transporte la declaración y la API valide por sí misma las selecciones desconocidas. No se creó fork ni se cambió ninguna versión de W1.
- D6: atribuir esfuerzo por **petición identificada**, no por intervalo de tiempo. Un título puede usar un esfuerzo diferente sin modificar la elección del usuario para el turno principal. Se sigue exigiendo exactamente una petición principal con el esfuerzo seleccionado, cero peticiones sin atribuir y cero despachos para una selección inválida.

Preparar W1 desde fuentes oficiales en lugar de redistribuir transitivas no auditadas. 1B-Desktop, distribución de producción y 2B no aprobadas.

**Revisión posterior · 2A aprobada para alcance experimental y 2B autorizada.** Se registra la [prueba interactiva básica en Windows 11](PHASE2A_REPORT.md#prueba-interactiva-básica-en-windows-11), separada de CI y sin aprobación amplia de 1B-Desktop. Para D5 en 2B: ZIP portátil, una raíz privada elegida al extraer, WinHTTP para descargas directas, Rust para verificación/extracción y Node/npm privados para los locks W1. Se descartó mantener Python portátil como auxiliar de la aplicación porque W1 se puede preparar con esos mecanismos; Python sigue instrumentando los ensayos. Un bloqueo cubre preparación y ejecución; el staging y la caché se mantienen en esa raíz. La alternativa de redistribuir el árbol npm o usar NSIS queda fuera del alcance aprobado. CI debe probar la preparación desde cero y las regresiones desde su resultado antes de emitir el ZIP. No cambia W1 ni se autoriza un release.
