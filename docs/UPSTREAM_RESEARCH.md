**? · Alcance Windows:** la publicación de un EXE no fija el mínimo común de build, CPU, WebView2 ni ABI de addons. Windows 11 x64 mantenido es el primer objetivo; registrar edición, build y CPU probadas. OpenCode [recomienda WSL](https://github.com/anomalyco/opencode/blob/v1.18.31/packages/web/src/content/docs/windows-wsl.mdx) para terminal, rendimiento y herramientas. El producto necesita pasar pruebas *nativas*; WSL no es un prerrequisito implícito. No hay certificación de Windows 10, Server, ARM64 o x86 del conjunto.

## Hallazgos que cambian el diseño

1. **CLIProxyAPI.** El [ejemplo v8](https://github.com/router-for-me/CLIProxyAPI/blob/v8.1.6/config.example.yaml) distingue claves cliente (`access.api-keys`) de proveedores (`api-keys`); `server.host` vacío escucha en todas las interfaces. Documenta compatibilidad con el YAML antiguo antes de una escritura v8. Los contratos v0 y v8 [se registran por separado](https://github.com/router-for-me/CLIProxyAPI/blob/v8.1.6/internal/api/server_management_v8.go). `management.disable-auto-update-panel` no evita la descarga en primer acceso si falta el archivo: verificar y distribuir el [panel](https://github.com/router-for-me/Cli-Proxy-API-Management-Center/releases/tag/v1.29.2) aparte o no habilitarlo.
2. **OmniRoute integrado.** El [manual de servicios](https://github.com/cheaper-inference/OmniRoute/blob/v3.8.50/docs/frameworks/EMBEDDED-SERVICES.md) describe instalación, arranque, estado y actualización de sidecars e incluso habla de npm para CLIProxyAPI. El [instalador real](https://github.com/cheaper-inference/OmniRoute/blob/v3.8.50/src/lib/services/installers/cliproxy.ts) usa releases de GitHub y genera configuración; `src/lib/services/bootstrap.ts` considera `autoStart` persistido. [binaryManager.ts](https://github.com/cheaper-inference/OmniRoute/blob/v3.8.50/src/lib/versionManager/binaryManager.ts) copia el ejecutable en Windows, busca `arm64` donde esta release de CPA publica `aarch64`, y solo compara el hash si hay suma aplicable. **P:** mantener CPA bajo control del supervisor nativo y configurar OmniRoute como cliente; no confiar el pin ni el rollback del conjunto al instalador integrado.
3. **OpenCode Desktop.** En esta etiqueta [`packages/desktop`](https://github.com/anomalyco/opencode/blob/v1.18.31/packages/desktop/package.json) usa Electron 42.3.3, Electron Builder, `@opencode-ai/app` y Solid; [`src/main/server.ts`](https://github.com/anomalyco/opencode/blob/v1.18.31/packages/desktop/src/main/server.ts) arranca el servidor mediante `utilityProcess.fork`, espera salud autenticada y gestiona su parada. Es una referencia útil de ciclo de vida, **no** una base Tauri lista para añadir dos ejecutables. [`packages/opencode/src/server/shared/ui.ts`](https://github.com/anomalyco/opencode/blob/v1.18.31/packages/opencode/src/server/shared/ui.ts) intenta cargar UI incrustada y, si falta, obtiene contenido de `app.opencode.ai`. No asumir funcionamiento local/offline por abrir una URL loopback.
4. **Conector OpenCode.** El [plugin oficial en el monorepo](https://github.com/cheaper-inference/OmniRoute/tree/v3.8.50/%40omniroute/opencode-plugin) declara 0.2.1, pero código etiquetado y publicado difieren. Se leyeron `package/dist/index.js` de los tarballs [0.2.1](https://registry.npmjs.org/@omniroute%2fopencode-plugin/0.2.1) y [0.2.2](https://registry.npmjs.org/@omniroute%2fopencode-plugin/0.2.2) en memoria, verificando `dist.integrity` SHA-512 en ambos. 0.2.1 proyecta `reasoning` y `toolcall`, pero no contiene el mapeo de `effort_tiers` a `reasoningEffort` presente en la fuente etiquetada; **0.2.2 sí lo contiene**. Ambos hacen lecturas en `/api/combos`; no confundirlo con el listado de metadatos `/api/v1/combos`. Preferir probar 0.2.2 fijado antes de escribir otro plugin. No confundir `@omniroute/opencode-plugin` con `opencode-omniroute-auth`, otro paquete/editor. La compatibilidad efectiva del hook con este OpenCode sigue abierta.
