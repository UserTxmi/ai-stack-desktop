## CLIProxyAPI 8.1.6: conexión y consumo son planos distintos

**V:** [rutas de consumo](https://github.com/router-for-me/CLIProxyAPI/blob/v8.1.6/internal/api/server_routes.go), [gestión v8](https://github.com/router-for-me/CLIProxyAPI/blob/v8.1.6/internal/api/server_management_v8.go), [despacho OAuth](https://github.com/router-for-me/CLIProxyAPI/blob/v8.1.6/internal/api/handlers/management/auth_files_v8.go) y [middleware](https://github.com/router-for-me/CLIProxyAPI/blob/v8.1.6/internal/api/handlers/management/handler.go):

| Operación | Contrato verificado | Uso propuesto |
|---|---|---|
| Disponibilidad/consumo | `GET /v1/models`, `POST /v1/chat/completions`; clave cliente separada de gestión | Salud autenticada sin inferencia facturable. Entregar a OmniRoute solo la clave de consumo. |
| Iniciar/cancelar OAuth | `POST /v8/management/oauth/auth-url` selecciona `provider`; `GET /v8/management/oauth/status`, `DELETE /v8/management/oauth/session` | El backend inicia un flujo admitido, abre el navegador del sistema, espera el estado con plazo y permite cancelar. Verificar URL, correlación, expiración y callbacks de cada proveedor antes de habilitarlo. |
| Retorno OAuth | GET/POST `/v8/management/oauth/callback` tienen registro separado del grupo autenticado de gestión | El proveedor y CPA gestionan el intercambio; el callback no es un login administrativo. No registrar query, código, device code ni `state`. |
| Administrar conexión | `GET /v8/management/credentials`, `PATCH /v8/management/credentials/status`, `DELETE /v8/management/credentials`; el middleware admite Bearer de gestión o `X-Management-Key` | Proyectar solo identificador opaco, estado y proveedor; desactivar o quitar con confirmación. Quitar localmente no prueba revocación remota. No usar importación/descarga de credenciales. |

**V:** El [handler OpenAIModels](https://github.com/router-for-me/CLIProxyAPI/blob/v8.1.6/sdk/api/handlers/openai/openai_handlers.go) filtra la lista ordinaria a `id`, `object` y opcionalmente `created`, `owned_by`. El registro interno más rico y la respuesta específica para `client_version` **no** son el contrato genérico que recibe OmniRoute. Ausencia de niveles aquí no significa que el modelo carezca de razonamiento.

## OmniRoute 3.8.50: aprovisionamiento repetible

**V:** [gestión de contraseña](https://github.com/cheaper-inference/OmniRoute/blob/v3.8.50/src/lib/auth/managementPassword.ts), [login](https://github.com/cheaper-inference/OmniRoute/blob/v3.8.50/src/app/api/auth/login/route.ts), [CSRF](https://github.com/cheaper-inference/OmniRoute/blob/v3.8.50/src/app/api/auth/csrf/route.ts), [nodos](https://github.com/cheaper-inference/OmniRoute/blob/v3.8.50/src/app/api/provider-nodes/route.ts), [conexiones](https://github.com/cheaper-inference/OmniRoute/blob/v3.8.50/src/app/api/providers/route.ts), [claves](https://github.com/cheaper-inference/OmniRoute/blob/v3.8.50/src/app/api/keys/route.ts). Son handlers del dashboard etiquetado: no asumir estabilidad entre releases.

**P · Secuencia de primera apertura:**

1. Arrancar el perfil nuevo con loopback explícito, exigencia de clave para inferencia y contraseña aleatoria de gestión. `INITIAL_PASSWORD` permite inicializar el hash; `POST /api/auth/login` valida contraseña y establece cookie. El cliente administrativo nativo conserva la sesión en memoria, respeta el flujo CSRF del dashboard y no pasa sus cookies al agente. Verificar exigencia **efectiva** de login y CSRF tras onboarding y reinicio.
2. Reconciliar un nodo `openai-compatible` por su ID guardado y atributos propios. Si falta, `POST /api/provider-nodes` con nombre, prefijo exclusivo, tipo de API según esquema de la etiqueta y `baseUrl` loopback de CPA con `/v1`; guardar `node.id` devuelto. `POST /api/providers` asocia ese ID en `provider` y la clave **cliente CPA** en `apiKey`. No duplicar conexiones tras timeout: releer por ID/atributos gestionados; si hay ambigüedad, pedir resolución. Nunca hacer *upsert* por el nombre visible de un nodo del usuario.
3. Crear vía `POST /api/keys` una clave de inferencia de OmniRoute con alcance mínimo y conexiones permitidas; guardar referencia en el almacén protegido. Si se pierde la respuesta que contenía la clave, revocar la creación incompleta identificable y emitir otra. No usar rutas de revelado. Verificar que la clave no sirve para `/api/providers`; comprobar catálogo con esa identidad. Para cuentas gestionadas directamente por OmniRoute, usar onboarding upstream autorizado en vez de duplicar el OAuth en CPA.
4. Guardar fase y objetos creados sin material sensible. Un error deja estado parcial reparable y conserva cambios ajenos. En migraciones confirmar cambios de esquema de las rutas. La guarda [de URL de proveedor](https://github.com/cheaper-inference/OmniRoute/blob/v3.8.50/src/shared/network/outboundUrlGuardPolicy.ts) distingue loopback/privadas de metadata; permitir solo el destino local elegido en el adaptador, no desactivar globalmente esta protección.

## Del catálogo a la petición efectiva

**V · Entradas:** [`/v1/models`, catálogo](https://github.com/cheaper-inference/OmniRoute/blob/v3.8.50/src/app/api/v1/models/catalog.ts) combina registros, modelos sincronizados y combos. Según la fila puede incluir `capabilities.tool_calling`, `capabilities.reasoning`, `capabilities.effort_tiers`, `context_length`, `max_input_tokens`, `max_output_tokens` y modalidades. Hay alias sintéticos y límites de reserva; no todo valor es una medición del proveedor. [`syncedCapabilities.ts`](https://github.com/cheaper-inference/OmniRoute/blob/v3.8.50/src/app/api/v1/models/syncedCapabilities.ts) considera niveles aprendidos y omite ciertos proveedores con mecanismo de sufijos propio. [`/api/v1/combos`](https://github.com/cheaper-inference/OmniRoute/blob/v3.8.50/src/app/api/v1/combos/route.ts) admite clave cliente válida o sesión; [`projectCombo.ts`](https://github.com/cheaper-inference/OmniRoute/blob/v3.8.50/src/app/api/v1/combos/projectCombo.ts) exige evidencia de todos los pasos concretos para `multimodal` y `reasoning`; `caching` es una opción del combo. Esto no acredita los niveles de esfuerzo ni el permiso de usar todos sus destinos.

**P · Un solo escritor del catálogo.** Primera opción: plugin oficial 0.2.2 fijado, comprobado como paquete en [Investigación](UPSTREAM_RESEARCH.md), sin credencial administrativa, con enriquecimientos opcionales desactivados si requieren privilegios. El escritorio consulta la vista efectiva de OpenCode y presenta frescura y errores. No ejecutar a la vez otro plugin de sincronización ni reescribir el JSONC global. Si el plugin no cumple los invariantes siguientes, usar un adaptador de catálogo limitado a este perfil sobre el proveedor compatible oficial, o contribuir la corrección upstream. No habilitar un selector que la petición real ignore.

| Invariante del adaptador (o prueba exigida al plugin) | Regla operativa |
|---|---|
| Identidad y permiso | Clave lógica `(perfil, instancia, ámbito de conexión, id exacto de ruta)`. Conservar barras, mayúsculas, alias y sufijos; nombre visible independiente. Para combos persistidos, cruzar `id` marcado `combo` con `name` de la proyección; las rutas virtuales van identificadas aparte. No mostrar como autorizado algo visto solo en catálogo global. |
| Capacidades y límites | Conservar valor y procedencia por campo, con estado sí/no/desconocido. Para combos exigir evidencia para **todos** los destinos permitidos; intersecar esfuerzos/modalidades/herramientas y usar mínimos de límites compatibles conocidos, sin confundir entrada, contexto y salida. Miembros desconocidos, anidados sin resolver o ciclos → desconocido. No inventar 128k ni enviar contexto recortado por memoria; si el SDK exige un límite no corroborado, señalarlo y bloquear esa ruta para sesiones que lo requieran. |
| Esfuerzo | Distinguir `reasoning=true` de lista de niveles. En el plugin candidato, tiers declarados → `variants[nivel].reasoningEffort`. [OpenCode `transform.ts`](https://github.com/anomalyco/opencode/blob/v1.18.31/packages/opencode/src/provider/transform.ts) varía por adaptador; puede generar niveles por defecto. Exponer solo valores corroborados; si solamente hay ID con sufijo verificado, enviarlo literal, sin añadir además opción de cuerpo. Nunca inferir soporte por el nombre ni equiparar presupuesto numérico con nivel textual. |
| Publicación fiable | Refrescar tras conexión/revocación, cambio de combo, petición manual y TTL con *jitter*; una actualización por ámbito. Validar esquema/tamaño/duplicados, descartar respuesta tardía de una generación revocada. Preparar snapshot completo, comparar hash, reemplazar atómicamente con su lista de propiedad; respetar entradas de usuario y conflictos. Persistir solo metadatos filtrados bajo ACL. |
| Fallos | Timeout, datos parciales o 5xx: conservar último válido marcado obsoleto, sin borrar modelos. Vacío confirmado y autorizado: publicar vacío. 401/403 o cuenta revocada: invalidar alcance, caché y selección de inmediato; nunca usar la caché como autorización. 429: respetar `Retry-After`, espera acotada, no rotar cuentas. Si desaparece un modelo, mantener el historial y pedir reselección; no redirigir una sesión activa. |

**Prueba decisiva:** en una ruta autorizada, registrar exclusivamente ID sintético y valor de esfuerzo en un receptor de ensayo. Verificar picker → modelo/variante del turno → adaptador de OpenCode → JSON de inferencia (p. ej. `reasoning_effort` en Chat Completions cuando corresponda) → traducción CPA → campo admitido por proveedor. Diferenciar «se envió» de «el proveedor lo aceptó». Probar dos niveles distintos, ausencia, rechazo y combo heterogéneo. No volcar prompts ni cadenas internas de razonamiento.

## OpenCode 1.18.31: espacio de trabajo, no segunda implementación de agente

**V:** [`serve`](https://github.com/anomalyco/opencode/blob/v1.18.31/packages/opencode/src/cli/cmd/serve.ts) y `web` arrancan servidor; `web` además abre navegador. El [SDK cliente](https://github.com/anomalyco/opencode/blob/v1.18.31/packages/sdk/js/src/client.ts) ofrece `createOpencodeClient`; en [`server.ts`](https://github.com/anomalyco/opencode/blob/v1.18.31/packages/sdk/js/src/server.ts), `createOpencodeServer` lanza otro `opencode serve`. Conectar el cliente al proceso existente. El [OpenAPI etiquetado](https://github.com/anomalyco/opencode/blob/v1.18.31/packages/sdk/openapi.json) incluye `GET /global/health`, `GET /project`, `GET/POST /session`, `GET/POST /session/{sessionID}/message`, `POST /session/{sessionID}/abort`, `GET /event` y `/global/event`, `GET /provider`, `GET /permission`, `POST /permission/{requestID}/reply`, `GET /mcp`, `GET /skill` y `PUT/DELETE /auth/{providerID}`. Usar una misma familia de API y el SDK/OpenAPI emparejado; no mezclar sus DTO con rutas nuevas `/api/...`.

**P:** abrir UI upstream contra el servidor ya iniciado con autenticación y carpeta consentida. OpenCode es dueño de historial, proyectos, eventos de partes de mensajes/herramientas y permisos. Al reconectar el flujo SSE, releer sesiones, mensajes y permisos pendientes; no duplicar un turno ni aceptar permisos por ausencia de evento. Usar proveedor compatible con `options.baseURL` local y credencial de inferencia de alcance reducido. `OPENCODE_CONFIG` configura un archivo adicional: las capas [se fusionan con precedencia](https://github.com/anomalyco/opencode/blob/v1.18.31/packages/web/src/content/docs/config.mdx). No garantiza por sí solo aislamiento. Validar rutas efectivas de estado/config/caché, plugins de proyecto, directorios Windows y colisiones con una instalación existente. **?** Recarga del catálogo en sesión activa y aislamiento de perfiles se demostrarán antes de ofrecer cambio sin reinicio.
