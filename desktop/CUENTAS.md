# AI Stack Desktop 0.0.6-dev · Windows x64

1. Extraiga el ZIP completo en una **carpeta NTFS privada nueva**, por ejemplo `%LOCALAPPDATA%\AI06`. Conserve la carpeta de 0.0.5-dev. Abra `bin\ai-stack-gentle.exe`. La primera preparación necesita internet y varios GiB libres; incluye Go y ejecuta el setup de Gentle Shell en su propio perfil.
2. Abra **Cuentas y administración** desde el icono de AI Stack en el área de notificación (puede estar en los iconos ocultos). Abra **CLIProxyAPI** y use la clave CPA que muestra esa ventana. En **OAuth**, elija el proveedor, abra su página oficial y complete la autorización. Si el proveedor requiere una devolución manual, use el campo de callback del mismo panel. No entregue la clave de gestión al proveedor. Utilice únicamente métodos autorizados para su cuenta y plan.
3. El supervisor prepara la conexión de OmniRoute con CPA. Tras conectar, espere la sincronización o pulse **Sincronizar ahora**. En una **sesión nueva**, elija `omniroute` y una ruta `cpa/…`. Use `/gentle:profiles` para asignar modelo y esfuerzo al orquestador y a sus agentes. Si desaparece una ruta, elija otra explícitamente. Solo se publican esfuerzos declarados por el registro activo. La aplicación no prueba cuentas enviando inferencias.
4. **OmniRoute** abre el dashboard de esta instalación. Cada panel usa un perfil propio de Edge y una clave local distinta. Gestione cuentas del chat en CPA; la clave de Gentle Shell se limita a esa conexión. No inicie otra instancia de CPA desde el dashboard. Cerrar Gentle Shell detiene el stack y los paneles. Las cuotas, las suspensiones y los permisos del proveedor siguen vigentes.

## Migrar credenciales compatibles de CLIProxyAPI desde Linux

La migración es opcional y manual. Parta de **una copia de seguridad** del `oauth.auth-dir` efectivo de CPA (`auth-dir` en configuraciones antiguas). Solo son candidatos los JSON individuales de credenciales de archivo que admite CPA 8.1.7 y cuyo proveedor permite trasladar la sesión. No copie bases de datos, cookies, archivos `.cds`, claves de gestión, configuraciones completas ni material ligado al llavero o al dispositivo. Para proveedores con tokens de refresco de un solo uso o si debe mantener la sesión Linux intacta, haga un login nuevo en Windows.

Prepare el portable una vez y cierre GPUI. Transfiera solo los JSON seleccionados por un canal cifrado a `datos\cuentas\auth\`, **sin sobrescribir** archivos y heredando los permisos privados del destino. Evite carpetas sincronizadas. Abra la aplicación, revise la cuenta en CPA y los modelos en Gentle Shell. Si CPA no reconoce el archivo, retírelo con el stack cerrado y use OAuth. Para una clave API configure el proveedor desde el panel, no copie `config.yaml`. Para revocar acceso use el proveedor además de retirar la credencial local.

Las claves de servicio del portable están ligadas al usuario Windows mediante DPAPI. Los archivos OAuth siguen el formato de CPA y se protegen mediante la ACL de `datos\cuentas`; **no comparta ni vuelva a empaquetar** un portable ya usado. Para volver a 0.0.5-dev, cierre GPUI y abra el EXE de la carpeta anterior; su perfil sintético no se migra.
