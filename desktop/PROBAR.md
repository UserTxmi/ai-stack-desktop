# AI Stack Desktop 0.0.1-dev · Windows 11 x64

1. En una VM de ensayo con WebView2 Runtime instalado, inicie sesión como usuario estándar. Descargue el ZIP `AI-Stack-Desktop-0.0.1-dev-win-x64` de Actions y extráigalo completo en una carpeta nueva, corta y privada, por ejemplo `%LOCALAPPDATA%\W1`. No ejecute desde el ZIP.
2. Desde PowerShell en esa carpeta, compare `(Get-FileHash .\ai-stack-desktop.exe -Algorithm SHA256).Hash` con `SHA256SUMS.txt`. `commit.txt` identifica el origen. La compilación de desarrollo no tiene firma de release.
3. Con red, ejecute `powershell -NoProfile -ExecutionPolicy Bypass -File .\preparar.ps1` (política sólo del proceso). Descarga desde los orígenes fijados, prepara Node privado/SQLite y verifica el parche. No instala Python en Windows. Reserve varios GiB. Si la política corporativa lo impide, documente el bloqueo sin elevar privilegios. Si falla, vuelva a extraer en otra carpeta y conserve sólo el nombre de la etapa fallida.
4. Abra `ai-stack-desktop.exe`; pulse **Iniciar stack**. Compruebe los tres servicios sanos y **Probar turno**. Debe responder el proveedor sintético. **Detener** debe registrar tres Jobs vacíos en orden OpenCode → OmniRoute → CLIProxyAPI. Repita, cierre la ventana con el stack activo y compruebe que puede arrancar de nuevo. No introduzca credenciales. Registre por separado build de Windows, WebView2, comportamiento visual y cualquier fallo sanitizado.
5. Al cerrar normalmente se elimina el perfil efímero. Tras una interrupción abrupta pueden quedar carpetas `demo-*` con datos sintéticos en `%LOCALAPPDATA%\AI Stack Desktop\Demo W1`; con la aplicación cerrada puede borrar **sólo esa carpeta de demo** y la carpeta extraída. Ningún runtime del stack se distribuye en el ZIP.
