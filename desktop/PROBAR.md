# AI Stack Desktop 0.0.2-dev · prueba manual en Windows 11 x64

1. Descargue el artefacto Actions `AI-Stack-Desktop-0.0.2-dev-win-x64` e **inicie sesión como usuario estándar**. Debe estar instalado Microsoft Edge WebView2 Runtime. Reserve varios GiB y extraiga todo el ZIP a una carpeta nueva, privada y escribible en un disco local NTFS, por ejemplo `%LOCALAPPDATA%\AI Stack 02`. Use una ruta corta (se admiten espacios). La ubicación de extracción determina dónde quedan todos los archivos de esta instalación. No mezcle el ZIP con la carpeta 2A.
2. `commit.txt` identifica la compilación. Puede cotejar el SHA-256 de `bin\ai-stack-desktop.exe` con `SHA256SUMS.txt` usando su verificador habitual. Es una compilación de desarrollo sin firma de release.
3. Abra `bin\ai-stack-desktop.exe` con doble clic. Compruebe la **ubicación de instalación** y el estado **Pendiente**. Con internet pulse **Preparar o reintentar**. Observe nombres de etapas y bytes de las descargas que muestren actividad. npm indica la etapa real sin porcentajes inventados. Al acabar deben aparecer **Preparado · integridad W1 comprobada** y la confirmación de SQLite.
4. Pulse **Iniciar stack**. Compruebe los tres servicios sanos y el catálogo `low / high`. Pulse **Probar turno** y confirme que respondió el proveedor sintético. No introduzca credenciales. Pulse **Detener** y compruebe el cierre OpenCode → OmniRoute → CLIProxyAPI → proveedor sintético.
5. Cierre y reabra. Debe indicar **Preparado** sin descargar. Pulse **Verificar runtimes**; comprueba de nuevo la integridad y SQLite. Vuelva a iniciar el stack, cierre la ventana con los servicios en marcha y compruebe que puede reabrirlo e iniciarlo otra vez.
6. En **otra carpeta de ensayo**, interrumpa la red durante una descarga y espere el error. Restaure la conexión y pulse **Preparar o reintentar**: se reutilizan los archivos verificados y se vuelve a descargar el archivo incompleto. Como prueba adicional, cierre la ventana durante la preparación; vuelva a abrir la misma instalación y reintente. No borre carpetas de otras aplicaciones.
7. Anote build de Windows, versión de WebView2, resultado de cada paso y cualquier etapa fallida. Los resúmenes `logs\preparacion.txt` y `logs\supervisor.txt` son locales. Si comunica un fallo, comparta sólo un resumen y retire nombres de usuario y rutas privadas. Los picos por Job no son RAM simultánea.

**Ubicación.** `bin` contiene el EXE; `runtimes`, los componentes; `config`, las configuraciones de demo; `datos`, los perfiles y WebView2; `cache`, las descargas y npm; `logs`, el diagnóstico; `preparacion`, los temporales. Cierre la aplicación antes de limpiar. Tras un cierre forzado pueden quedar `demo-*` sintéticos en sus carpetas propias. Para cambiar de ubicación, extraiga una copia limpia en otra carpeta: las dependencias workspace usan enlaces NTFS con destino absoluto y esta versión no migra instalaciones. WebView2 y las funciones de Windows necesarias para ejecutarlo se mantienen a nivel de sistema.
